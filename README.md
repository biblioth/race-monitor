# 每日赛事与户外活动监控

独立仓库：[biblioth/race-monitor](https://github.com/biblioth/race-monitor)。采集、部署、状态与通知队列由本项目独立维护。

每天北京时间 **09:00** 由 Cloudflare 触发 GitHub 采集，检查完成后通知**原飞书机器人和新增群机器人**。有新增就发活动消息，**无新增也发一条简短检查结果**；通知时间取实际检查完成时间，并非固定在 09:00 发送。

## 每日运行和通知

以下时间均为北京时间。

| 时间或情况 | 行为 |
| --- | --- |
| 09:00 | Cloudflare 直接调用 GitHub API 触发采集 |
| 当天尚未完成 | 每隔 30 分钟尝试补跑，最多触发 6 次；运行中的采集不重复触发 |
| 检查完成，有新增 | 两个机器人分别收到新增活动；WTM 新增亚洲成员单独通知 |
| 检查完成，无新增 | 两个机器人各收到一条“今日无新增”；当天补跑和手动复查不重复发送 |
| 部分来源读取失败 | “无新增”消息标注“部分来源异常，详见告警。”，来源异常／恢复另行通知 |
| 全部来源读取失败 | 发送故障告警，不发送“今日无新增”，不更新已通知活动基线 |
| 09:45 仍未完成 | 两个机器人各收到一次超时告警；补跑完成后各收到一次恢复通知 |
| 10:17 | GitHub 自带定时作为独立备用触发；当天已完成就跳过浏览器安装和采集 |

Cloudflare 每 5 分钟检查一次当天状态和待投递消息。GitHub 自带定时可能延迟，因此只作备用。两个机器人的投递和失败重试相互独立。

## 范围和提醒

| 分类 | 范围 |
| --- | --- |
| 越野跑UTMB | 仅亚洲 UTMB World Series；按官方赛历洲别筛选，不含欧洲 Mont-Blanc 总决赛及 UTMB Index 积分赛 |
| 越野跑WTM | 环富士山、港百；其他已有成员不监控报名 |
| 马拉松A类赛事 | 仅江苏、浙江、上海的全马、半马；通过最酷发现及核验当届 A 类依据，区分平台声明与目录计划类别 |
| 品牌活动 | 凯乐石、始祖鸟举办或合作的越野跑、路跑／马拉松、攀岩；重点上海及沪苏浙皖 |

- 活动提醒只通知新赛事／新届次／新活动；每日检查结果和必要故障通知单独发送。同届项目的报名变化、增加组别、改名、改期和临近截止均不再次提醒。
- 新增消息里保留当次可核实的报名时间、地点、组别、费用、资格及链接；缺少信息写“待公布”。
- 首次启用汇总仍可报名及已有报名预告的项目，可能分多条消息；以后有新增就通知，无新增也发送一条简短检查结果。
- WTM 新增亚洲成员单独提醒，不自动纳入报名监控。基线已含港百、环富士山、越南 VMM，VMM 不会误报为新增。
- 报名预告已提醒过的项目正式开报时不会再推送。
- 必要的来源异常／恢复另行通知，同一持续异常不会每天重复。
- 每天完成检查且无新增时，两个机器人各收到一条检查结果；日期和时间取实际完成时间。同一天补跑、手动复查不重复发送，有新增活动或 WTM 新亚洲成员的批次不再附发“无新增”。部分来源异常时明确标注，全部来源失败则只发故障告警。未按时完成的告警按日期去重，恢复只发一次；触发 API 返回成功不等于采集已完成，必须以 D1 当天批次记录为准。

## 实现

```text
Cloudflare 每 5 分钟检查北京时间与当天完成状态
  → 09:00 调用固定 GitHub 工作流；需要时每隔 30 分钟补偿
  → GitHub 每日 Python 采集（6 个并发请求，单来源最多 3 次尝试）
  → 官网结构化赛历、最酷A类分页列表与报名页
  → 核验届次、范围、A 类及品牌证据
  → 合并跨来源报名入口、同届日期与归一化名称，仅生成首次新增
  → 带赛事专用管理员令牌提交 Cloudflare
  → D1 同一事务保存状态与通知事件（版本号防止并发覆盖）
  → 赛事专用通知队列重试发送
  → 原飞书机器人＋新增群机器人
```

采集运行在本仓库的 GitHub Actions。状态与飞书通知使用独立的 Cloudflare Worker `race-monitor`、D1 `race-monitor`、队列 `race-monitor-notifications` 及死信队列。D1 长期保存去重记录，通知同时发送到原飞书机器人和新增群机器人，两边独立去重、投递和重试。Worker 每 5 分钟检查当天是否需要触发、是否超时，并补发待投递消息；正常完成的赛事采集保持每日一次。

港百及其WTM成员页在直连受限时，先尝试官网 HTML 声明的公开 WordPress API。港百和凯乐石还可尝试通过 Worker 读取固定的公开来源。备用接口仅接受预设来源名称，独立管理员令牌只用于访问自己的 Worker，不会转发给赛事官网；港百这些路径仍受限时，使用 GitHub 上的独立 Chromium 匿名读取官方主页和 Entry 页，只在读到当届年份及报名规程时认定成功。不会使用个人浏览器、登录状态或人工验证码方案；全部路径都失败时报告覆盖异常。

港百隔离浏览器按首页、报名页分别读取，每页最多尝试两次，失败后间隔 2 秒重试；已成功的页面不重复读取。连接建立后等待赛事正文出现，避免无关资源拖延页面加载事件而误报超时。持续失败时标明页面、连接／正文阶段、HTTP 状态及是否停留在访问校验页；旧的成功记录保留为“最后成功读取”，不作为本轮读取成功。

采集任务先取得 25 分钟执行租约，运行上限 23 分钟；租约过期后可补偿被中断的批次。D1 中的 `race_scheduler_days` 以北京时间日期记录触发次数、状态与告警；原子认领防止重叠 Cron 重复调用 API，单日最多 6 次触发。API 超时也会等待 30 分钟再试，最终仍以采集自身的日期去重、25 分钟租约和版本提交防止重复发现。告警与两路待投递记录原子写入，发送失败不会被记为成功。队列退避重试，超过队列重试次数的待发记录仍保留供扫描补发。Webhook 没有接收端幂等键，极端情况下发送成功但响应丢失可能产生重复投递。

## 来源与边界

- UTMB：读取官网完整嵌入赛历，而非只取可见第一页；仅对官方洲别为 Asia 的分站读取组别和报名入口，缺少洲别的条目暂不推送。
- 环富士山：官网当届大会要项、普通报名窗口，保留日本时间并转换北京时间；优先通道不当成普通开报。
- 港百：官网当届信息和 Entry 规程；慈善报名入口单独标识，不声称有剩余名额。
- WTM 成员：港百与环富士山官方 WTM 成员目录互为备用；总站可访问性及成员同步存在限制。
- A 类：以最酷 A 类标签赛历和最酷报名列表为每日发现入口。赛历逐页读取至全部为历史赛事的一页，最多 20 页；分页失败、循环或达到上限会保留已发现条目并报告覆盖不完整。按列表及当届详情的实际省份筛选江浙沪，全马／半马候选合并后读取详情及最多两篇关联报名公告／规程。侧栏推荐和全站导航不作为当前赛事的报名或 A 类依据。
- A 类核验：当届详情明确声明 A 类时标注“平台转载，未独立核实最终认证”；仅有 A 类标签、仅申报／拟认证、只有上一届依据的项目放入待核验列表。待核验条目每天重新检查，尚未通知的条目不会被提前加入已通知去重状态。历史田协目录快照仅作同届计划类别的辅助依据，不能阻断平台发现；不再每日请求 PDF 或在望赛历。资料不足或报名信息未公布时不推送，信息齐备后首次推送。
- 马拉松比赛日期：核对同届报名页、赛事页的日期栏及独立正文。标有“待定／暂定／预计”等文字的日期栏不作为确定日期，不能把旧的列表月份当作比赛月份；正文明确给出本届赛事的开赛日期时可采用，并在消息中注明“正文公布，日期栏待定”。报名开放、截止、领物接驳、历史届次及其他赛事的日期不能充当比赛日期。多个确定日期互相冲突时保留为待核验；没有可靠比赛日期则显示“时间待定”。日期依据随状态保存，同届日期修正不会再次触发新增通知。
- 马拉松覆盖报告：`marathon_coverage` 分别记录读取页数、扫描条目数、分页是否完整、江浙沪候选数、详情成功数、核验通过／待核验数、可推送数及详情失败数。`registry_count`、`a_class_count` 仅是历史辅助目录统计，不代表实际监控覆盖量。
- 品牌：朗途中文官网和最酷。始祖鸟官网已按用户要求移除，不再读取或监测其更新；最酷里的始祖鸟关键词检索和活动筛选继续保留。凯乐石官网按用户选择暂时停用。
- 最酷品牌发现：每日读取报名首页，并按“凯乐石、KAILAS、FUGA、始祖鸟、ARC'TERYX、ARCTERYX”检索；支持同关键词下一页，最多 10 页，分页中断会报告覆盖不完整。真实无结果页算正常空结果，登录／验证页算失败。日期和地点取实际信息段，忽略宣传语及延期说明。
- 最酷品牌详情：合并链接后仅抓一次详情；同时核对首页中长三角尚未结束的跑步／攀岩候选，不要求品牌出现在标题里，以免漏掉仅在正文标注的合作。地域、日期、状态和品牌证据均取当届独立正文，站点导航及推荐区不能提供证据。名称明确标注凯乐石／始祖鸟，或明确标注 FUGA 训练／跑山系列的项目，可按平台信息推送并保留最酷来源；合作证据类型保存在内部状态，消息不附“品牌关系未独立核实”等说明。正文明确写出主办／冠名／赞助／合作关系时注明平台正文依据。普通装备推荐及仅零散出现 FUGA 的条目留待核验。品牌与 A 类认证分别核验，品牌标注不会自动变成 A 类依据。
- 朗途：使用[中文官网](http://www.letoursports.com/)，从首页发现赛事／户外活动分类，分页读取，合并同一活动 ID 后核验当届中文详情。日期、组别、费用来自公开场次数据（仅解析 JSON5，不执行脚本），地点及品牌依据限当届正文，报名状态取当届页面按钮。排除已结束、进行中、报名截止及赛后邮寄、展位押金、纪念勋章等服务项目；资料不足则留待核验。中文版当前 HTTPS 证书与域名不匹配，因此匿名读取公开 HTTP 页面，不关闭证书校验，不发送凭据或提交报名。英文展示站已停止监控。
- 品牌覆盖报告：`brand_coverage` 记录各关键词命中数、搜索页数与完整性、去重后的列表条目及地域候选数、详情读取／失败数、品牌核验与可推送数；实际通知还会与长期已通知状态合并去重。

**线上验证结果**：港百普通 HTTP 请求在 GitHub 与 Worker 受限，GitHub 独立浏览器已成功读取官方主页，已接入浏览器备用读取；凯乐石官网在 HTTP 与普通独立浏览器中均返回 405，用户于 2026-10-23 选择暂用朗途、最酷补漏，官网来源暂停每日采集。暂停不算读取成功或恢复，官网独有活动仍可能漏检。对已启用来源持续重试并通知异常／恢复；暂停的凯乐石官网不会每日重试。WTM 成员清单已由环富士山官方备用页正常获取。

**2026-10-28 港百访问异常**：09:00 定时任务正常启动，港百 HTTP、公开 API 和 Worker 备用读取均返回 403，浏览器原先只报告超时；其他来源继续处理，异常通知已投递两个机器人。Linux 和 macOS 复查均未能完成港百核验。已增加每页一次重试、等待实际正文及分页面诊断，[109 项测试通过](https://github.com/biblioth/race-monitor/actions/runs/40624505525)。[改动后线上复查](https://github.com/biblioth/race-monitor/actions/runs/40624529588)进一步定位到报名页：HTTP 403，访问校验页未恢复，两次尝试后仍失败。港百保留异常状态和 10 月 27 日的最后成功读取时间，当前未宣称云端访问已恢复；恢复后仍按原规则通知。

**当前未覆盖**：始祖鸟官网已主动移除，仅通过最酷补充发现相关活动。会员小程序内页、微信群、仅在海报图片中发布的招募；国内组委会公众号也未全量接入。公开平台收录存在延迟，不能承诺全量覆盖。24 小时两轮之间开放并结束的短时活动可能错过。每次报告和 `/races/health` 均显示覆盖缺口。

## 飞书消息

```text
🏃 新增活动 {数量} 项｜{日期}

🆕 {名称及届次}
分类：{越野跑UTMB／越野跑WTM／马拉松A类赛事／品牌活动}
{活动日期}｜{地点}
项目：{已知组别，较长时缩略}
报名：{状态}｜截至 {截止时间}（北京时间）
来源：最酷
入口：{报名链接或小程序路径}
```

项目、费用及报名时间仅在已知时显示；有多个组别报名窗口则分别保留，时区不省略。最酷信息保留来源标识，A 类信息保留简短依据说明，官方来源不重复列链接。取消固定资格提示、重复原文链接、核验时间和覆盖统计；完整资料仍保存在状态及运行报告中。无报名链接时用官方原文入口。活动消息仅通知新增，报名变化和临近截止不提醒。分片按 UTF-8 字节数限制，保留完整活动条目。

无新增时，每天发送一次以下检查结果至两个机器人：

```text
🏃 赛事监控｜今日无新增
2026-10-27 09:05（北京时间）
检查完成，数据源正常。
```

部分已启用来源读取失败时，末行改为“部分来源异常，详见告警。”；同一持续来源异常仍不重复发送详细告警。`daily_notification` 与日常批次及消息原子保存，`race_no_new` 按北京时间日期在 D1 中去重，不会因备用触发、补跑、手动复查或队列重试重复生成消息。当天已发过新增，后续没有新增的复查不再附发空结果。

## 部署与运维

1. 为本项目配置独立的 D1、通知队列与死信队列，并更新 `cloudflare/wrangler.jsonc` 的资源绑定。
2. 在 `cloudflare/` 执行 `npx wrangler d1 execute race-monitor --remote --file=./schema.sql`，再执行 `npx wrangler deploy`。
3. Worker Secrets：`ADMIN_TOKEN`、`GITHUB_DISPATCH_TOKEN`、`FEISHU_WEBHOOK_URL`、`FEISHU_WEBHOOK_SECRET`、`FEISHU_ALERTS_WEBHOOK_URL`、`FEISHU_ALERTS_WEBHOOK_SECRET`。管理员令牌为赛事项目独立生成；旧机器人沿用原设置，新增群使用独立 URL 和签名密钥。GitHub 触发凭据只作为 Worker Secret 保存，不进入仓库、运行报告或接口响应；可使用具备本仓库 Actions 写入权限的细粒度令牌，或具备 `repo` 权限的现有 OAuth 授权。目标仓库、工作流和分支固定，禁止跟随重定向。
4. 本仓库 GitHub Secrets：`RACE_MONITOR_ADMIN_TOKEN`（与 Worker 的 `ADMIN_TOKEN` 相同）、`FEISHU_WEBHOOK_URL`、`FEISHU_WEBHOOK_SECRET`、`FEISHU_ALERTS_WEBHOOK_URL`、`FEISHU_ALERTS_WEBHOOK_SECRET`。GitHub 飞书配置仅用于整个采集任务失败时向两个机器人分别发送告警。
5. 手动执行 `preview=true` 验证真实来源，再执行正式任务。Worker 的 `SCHEDULER_ENABLED=true` 启用主触发；仓库变量 `RACE_MONITOR_ENABLED=true` 允许 Cloudflare 触发和 GitHub 备用定时执行。暂停监控时将两处都设为 `false`。手动任务和预览不受开关影响。新迁移必须先导入原去重状态，再启用定时任务。
6. 手动执行工作流 `Verify Cloudflare scheduler`，验证健康状态、双机器人配置、接口鉴权，并让 Worker 实际触发一次每日任务。当天已完成时该任务退出，不重复推送；尚未完成则执行当天采集。调度故障测试使用本地模拟数据库和假机器人，不向真实群发送故障测试消息。

手动复查：工作流 `refresh=true` 会重查当天来源并沿用 D1 去重，只通知尚未发现的合格项目；不会重新推送已有活动。正常日常采集保持每天一次。`preview=true` 进入无写入／无通知预览，结合 `refresh=true` 也不会写入状态。`--check-needed` 是只读预检，与 `--preview` 互斥；不会采集或取得租约，仅供工作流跳过不必要的浏览器安装。

去重先使用稳定项目 ID 和同届报名入口，再比较同届日期及归一化名称，保存跨网站入口别名。报名链接中的跟踪参数不生成新项目；其他站点 URL 的活动 ID 查询参数会保留。相同活动跨品牌／A 类分类只发送一条，优先保留 UTMB、WTM、A 类赛事分类。不同年份、不同日期的独立场次保留，证据不足不会消耗首次通知机会。

接口：

- `GET /races/health`：公开的运行状态、来源覆盖、待投递数量及当日调度摘要，不含凭据或完整活动状态；启用主调度时，09:45 当天尚未完成即返回 503，不再等待旧的 26 小时新鲜度阈值。
- `GET /races/state`：需本项目 `ADMIN_TOKEN`，读取版本和完整去重状态。
- `GET /races/source?name=...`：需本项目 `ADMIN_TOKEN`，读取预设白名单内的公开页面，不能传入任意 URL。
- `POST /races/commit`：需本项目 `ADMIN_TOKEN`，对状态和待发事件做原子版本提交，冲突返回 409。
- `POST /races/scheduler/dispatch`：需本项目 `ADMIN_TOKEN`，让 Worker 实际触发固定的每日工作流，供部署验证与手动补跑；不接受其他仓库、分支、工作流、任意 URL 或刷新参数。

GitHub Actions 每轮保存来源报告 30 天；D1 长期保留赛事身份、成员基线和赛事投递去重记录。本项目不包含订位监控代码或其他项目的运行状态。

历史目录快照来源、PDF SHA-256、提取结果校验值和核验时间保存在 `race_monitor/data/caa-2026.json`。该文件只包含公开赛事事实，不含报名状态；2026 年快照不能为 2027 年赛事提供 A 类依据。旧 D1 中已经保存的核验快照仍可使用，每日任务不再下载或自动刷新 PDF。更新辅助目录时应重新核验原文件年份及提取结果，再更新快照。
